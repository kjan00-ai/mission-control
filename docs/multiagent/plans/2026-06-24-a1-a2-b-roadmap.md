# A2 → A1 → B 착수 로드맵 (C6 마무리 → C7 진입)

> C6 메커니즘은 구축 완료·default-off·적격 0(O1). 활성화 증거(인간 거부 라벨)가 유기적으로 거의 안 쌓여
> **무기한 보류** 상태. 해법은 "증거를 기다림"이 아니라 **증거 정의를 인간거부 → MAIA L2 검증으로 전환(B)**.
> 단 B의 안전성 = L2의 **신뢰성(transport) × 독립성(model)** 에 직결되므로 **A1(L2 네이티브 전환)이 B의 전제**.
> A2(게이트 자기보호)는 B의 정책 편집 안전 전제라 가장 먼저. 전 단계 default-off·대표 게이트·가역 불변.

## 0. 실측으로 드러난 전제 (계획을 규정하는 사실)

1. **l2-loop는 Stop 훅(`hooks/post-task-l2.js`)/cron이 spawn하는 독립 detached node 프로세스** —
   Claude 세션 컨텍스트가 없어 **Agent/Workflow 툴을 직접 호출할 수 없다.** 따라서 "네이티브 전환"은
   단순 함수 교체가 아니라 *헤드리스에서 작동하는 검증 transport* 설계다. (l2-launch.js = Windows→WSL 브리지/폴백)
2. C6 L2의 안전 가치 = **codex ∥ gemini 독립 교차검증**(서로 다른 벤더·적대적). 이를 Claude-only로 합치면
   "Claude가 Claude 산출물을 검증" = 상관된 맹점 → **B가 그 pass를 자율 활성화 근거로 쓰면 안전모델 과장**.
3. (오늘 선반영) CLI 매체 불안정은 `l2-loop.js` 재시도 계층으로 1차 완화됨(transient 재시도 / terminal 즉시포기)
   — 그러나 외부 CLI 의존인 한 인증·쿼터·timeout은 근본 미해결. A1이 정공법. [[l2-cli-invocation-gotchas]]

## 1. 단계별 계획

### A2 — 게이트 자기보호 격상 (선행, 작음) — B의 안전 전제
- **변경**: 게이트 SSOT(`~/.ai-bootstrap/{decision-policy.json,risk-classify.js,c6-policy.json,policy-classify.js,maia-manifest.json}`,
  `~/.claude/hooks/**`, settings.json hook 등록부) 편집 = 현 T2(ask) → **"대표 `!` 전용(owner-only)"**.
  즉 **에이전트의 편집은 deny / 대표가 `!`로 직접 실행하는 편집은 통과**. (전면 DENY 아님 — 아래 L2 정정)
- **★ L2 정정(18a9acf4·42d48d76)**: 전면 DENY로 막으면 *정책 튜닝 때마다 대표가 매번 강제승인/직접 JSON 편집* =
  **C6가 없애려던 모달 피로의 재발**이고, B의 "대표 sign-off로 c6-policy 활성화"와도 충돌한다. 해법 = **행위자 구분**:
  게이트는 *에이전트 자가편집*만 deny, *대표 `!` 편집*은 마찰 없이 통과. 이러면 A2(자기보호)와 B(대표 활성화)가
  같은 메커니즘으로 양립(대표=통과, 에이전트=차단). managed-only(엔터프라이즈 잠금)는 C7 강제형 배포 때로 이연.
- **왜 B보다 먼저**: B는 `c6-policy.json` 활성화 플래그를 다룬다. 자기보호 없이는 에이전트가 자기 게이트를
  스스로 켤 수 있음(자기참조 취약점, spec §6.2). B 활성화 전에 못박아야 한다.
- **검증**: 에이전트 게이트 SSOT 편집 → deny 관측 / 대표 `!` 편집 → 통과 관측 / 기존 risk-classify 회귀 0.
- **가역**: 등급 한 줄 환원. 규모 반나절.

### A1 — L2 검증기 네이티브 전환 (C7 최대 관문)
**A1.0 확정 구성 (대표 결정 2026-06-24)**: **Claude 서브에이전트(기술 관점, 주) + gemini API 직결(운영·UX 독립 2nd).**
codex CLI·gemini CLI 셸아웃 제거. 벤더 다양성 유지로 "Claude가 Claude 검증" 약점 회피 → B 증거 신뢰성 보존.

- **A1.1 in-session 동기 경로**: 에이전트가 직접 동기 L2를 돌릴 땐 **실제 Agent/Workflow 툴 사용**(구조화 출력·즉시 신뢰성).
- **A1.2 headless auto 경로**(Stop 훅·cron): transport **= Claude Agent SDK로 확정**(claude -p 대안은 폐기 — L2 5d77f14b:
  "둘 중 하나로 확정"). SDK = 인프로세스·StructuredOutput schema 강제로 parser-fail/빈출력을 **구조적으로 제거**.
  단 **timeout·인증·rate-limit은 "제거"가 아니라 "대폭 감소(잔존 인정)"**로 표현 정정(L2 5d77f14b: §4와 정합). 오늘 재시도 계층 재사용.
- **A1.3 gemini = API 직결**(`~/.gemini/.env` 키): CLI trust-prompt·shim·IneligibleTier CLI 함정 소거. 독립 2nd 관점.
- **A1.4 codex/gemini CLI = opt-in 폴백 유지(제거 아님)** — 단 **(가) 배타적·순차 아님**: API 실패를 먼저 분류
  (terminal/transient) 후에만 폴백, **전체 wall-clock 상한 + 프로세스그룹 kill** 보장(L2 88b1efca: API+CLI 타임아웃
  중첩·detached 좀비화 방지). **(나) 폴백으로 산출된 verdict는 B 증거 자격 없음 → `incomplete` 강등·evidence 제외**
  (L2 aa98e0b7: 폴백 결과가 B 증거에 섞이면 A1 신뢰성 전제 붕괴).
- **검증**: 독립성 보존(두 벤더 관점 유지) / `l2-loop` 55테스트 무회귀 / parser-fail율↓ 실측 / 폴백 좀비 0(프로세스
  카운트) / maia-deploy drift0 / 비용·latency 측정. 각 하위단계 산출물 동기 L2.
- **불변식**: 기존 집계·심화·escalation 로직(`l2-schema.js`) 무변경 — transport만 교체. overallVerdict의 incomplete(허위 pass 방지) 유지.

### B — 검증 우선 증거 모델 (A1 후)
- **★ B.1 양성 증거 정의 — 근본 재설계(L2 BLOCKER e3b4423f + cf43de95, codex·gemini 독립 합치)**:
  당초안 "(C6 allow + L2 pass + **인간거부 0**)"은 **치명적 결함**. "인간거부 0"은 *아무도 안 본 미검토(unreviewed)* 와
  *명시적 승인* 을 구분 못 해 → **미측정값을 안전 증거로 승격 = Silent Trigger**(대표가 인지 못 한 채 자율 진입).
  → **수정: 증거는 "관측된 양성 합치"만.** 양성 증거 = **(C6 allow + L2 pass + 인간이 *실제로 검토한* holdback 표본에서 거부 0)**.
  미검토 건은 **증거 아님(중립)** — 부재를 승인으로 읽지 않는다. holdback은 "샘플 유지"가 아니라 **인간 관측을 *보장*하는
  강제 표본**(관측 없으면 증거 0). shadow audit 병행.
- **B.2 `c6-trust` 신규 적격 기준**: doubleDanger(🚨🚨)=0 유지 + **최소 표본수 게이트**(L2 6e1cf20c·4c337868:
  `N_min` 미달 카테고리는 ready 절대 불가 — 1~2건 우연통과 오발동 차단) + L2 검증 임계(L2-blocker율 < X) →
  "L2-backed ready" 산출. **N_min·X는 기획결정 → B.2 이후 단계 진입 전 대표 명시 결재 게이트**(shadow 데이터로 보정).
- **B.3 `c6-cutover`/`c6-policy` 활성화 배선 — 원자성(L2 89907487)**: cutover는 여러 SSOT+큐를 바꾸므로
  **atomic write + lock + idempotency key + 부분실패 롤백**으로 정책/큐/enforcement drift 차단. 활성화 편집은
  **대표 `!`**(A2의 owner-only와 동일 메커니즘 — 에이전트 deny, 대표 통과).
- **B.4 shadow 기간 → 대표 카테고리별 활성화**(점진). cutover/queue 라이브 효과는 이때 최초 발생.
- **불변식**: hard_deny/DENY 영구 제외. **폴백(CLI)으로 산출된 L2 verdict는 증거 자격 없음**(A1.4-나). 활성화 편집은
  A2로 보호된 대표 `!` 전용. 3중 가역(flag/env/policy).

## 2. 의존·임계경로
- **A2 → A1 → B** 순. A2는 B 전제(정책 자기보호), A1은 B 전제(증거 신뢰·독립).
- A1.1(in-session)은 A1.2(headless)보다 단순 → 먼저 가치 실현 가능.
- B는 A1 완료 후에만 안전. A1 없이 B를 켜면 불안정/저독립 L2 pass로 자율을 정당화 = 위험.

## 3.5 A1.1 PoC 결과 (2026-06-24) + 2차 L2 잔여 (Agent-L2 round)
- **A1.1 실증**: in-session Agent 툴 L2 작동(구조화 출력·l2-schema 호환). **CLI L2가 놓친 A2 Bash 우회 BLOCKER를 포착** = A1 가치 입증.
- **A2 BLOCKER 해소(`1f6af1b`)**: gate-self path-glob이 Edit/Write만 잡던 구멍 → denylist `gate-write-bash`(DENY)로 Bash 쓰기 벡터 차단. 204/204·drift0. [[a2-gate-self-protection]]
- **잔여 important(2차 L2, 구현 시 반영)**:
  1. **B.1 관측 측정 메커니즘 미명세** — "인간이 실제 검토" vs "반사적/자동 승인" 구분·기록 방법 부재(현 shouldHoldback=랜덤 ask 모달일 뿐). 트랜스크립트는 `rejected`만 고신뢰 복원([[transcript-modal-response-source]]) → **양성 증거 = "거부 기회 노출 + 거부 0"로 정의**하되 "검토함" 능동 입증은 B 기획결정으로 이연. (Silent Trigger 약화판 잔존 인지)
  2. **A1.4 폴백 incomplete ↔ B.2 N_min 교착** — 폴백 verdict는 N_min 모집단 제외인데, 폴백 빈발 시 N_min 영구 미달=무기한 보류 재현. → 폴백율 자체가 A1 미완 신호(카테고리 보류는 정상), A1 완성도가 B 전제임을 명시.
  3. **행위자 구분 근거** — "대표 `!` 통과"는 `!`가 PreToolUse 훅 미경유라 성립(에이전트는 `!` 불가). 단 에이전트 Bash 우회는 gate-write-bash로 차단(위 1f6af1b). 훅은 호출 주체를 직접 구별 못 함([[decision-gate-scans-command-text]]) — 텍스트/도구 기반 방어, 완전강제는 C7 OS권한.
  4. **manifest 일관성** — A2 보호 "명시 대상"에서 maia-manifest.json은 T2 유지(배포분류·dev 마찰)로 범위 확정. settings hook-registry는 이연.
  5. **A1 자기참조 순환** — 전환 중인 L2 transport로 전환 산출물 검증 → 전환 기간 검증은 **구 transport(현 codex/gemini CLI) 고정**.
