## D-1. GLM 호출 방식 = 서브에이전트 위상 (핵심 결정)

### 문제
GLM은 "대량 코드생성·디자인 구현 보조 생성자"로만 편입된다(메인 교체 아님). 일상 작업에서 GLM을 **어떻게 부르는가**가 곧 **서브에이전트 위상**을 결정한다. 대표님 "에이전트 SDK 도입 금지" 규약이 선택지를 제약한다.

### 선택지

| 방식 | 대표님 조작 | Task 서브에이전트 위상 | SDK | 비용/통제 |
|---|---|---|---|---|
| **A. 세션 백엔드 스왑** | 대량작업만 백엔드를 GLM으로 세션 실행 (CLI 동일) | GLM 세션 → 그 세션의 Task 서브에이전트도 **GLM 상속** | 불필요 | 세션 단위 격리, 롤백=세션 종료 |
| **B. 수동 이원화** | 작업 성격 보고 GLM용/Claude용 세션 직접 선택 | 각 세션이 자기 백엔드 상속 | 불필요 | 통제 최대, 매번 판단 부담 |
| **C. Claude 오케스트레이션** | 항상 Claude에 지시, Claude가 대량생성만 GLM 위임 | GLM이 Claude의 서브에이전트/도구가 됨 | **필요** | 편의 최대, **규약 충돌·API 추가과금** |

### 권고 = **A (세션 백엔드 스왑) 잠정 방향 — 확정은 tool-use 스모크 게이트 통과 후** (L2 `d948e323` 반영: 순서 역전 해소)
> ⚠️ A/B의 성립조건(GLM 백엔드에서 Task 서브에이전트·tool-use 정상 동작)이 미검증이므로 **지금 A/B를 "확정"하지 않는다.** 검증을 뒤로 미룬 채 결정하면 단계 의존성이 역전된다. → 성립조건을 **PoC 착수 게이트로 전진 배치**하고, 통과 시에만 A를 확정한다.

- **게이트 순서(확정)**: ① GLM 엔드포인트 연결 + **tool-use/Task 서브에이전트 스모크**(상위계획 §6 2단계에서 실측) → ② 통과 시 A 확정 / 부분통과 시 축소모드(아래) / 실패 시 **B로 폴백 or GLM 편입 보류**.
- 근거 1: SDK 불필요 → "에이전트 SDK 금지" 규약 무충돌.
- 근거 2: 조작 방식은 동일하나 **학습비용 0은 과장**(L2 `cc3264d1`) — 백엔드 env 전환 절차의 인지부담·오설정 리스크 존재. → **전환은 스크립트/래퍼 1개로 고정**(수동 env 편집 금지)해 오설정 차단.
- 근거 3: 세션 단위 격리 → GLM 산출물이 세션 경계로 분리돼 L2 티어 검증 부착이 명확.
- C는 배제하지 않되 **별도 결재 게이트**(SDK·과금 고지 후)로만 재검토.

### 축소모드 정의 (L2 `7734827d`+`a56380dd` 반영 — 폴백의 운영목표·전환절차 명시)
tool-use 부분통과 시 A를 "서브에이전트 없는 단발 생성"으로 축소하되:
- **L2 목표 유지법**: 서브에이전트 없이도 GLM 산출물은 **세션 종료 후 산출 파일 단위로** L2 티어 검증(codex∥gemini∥Claude)에 부착 → concordance·티어링 지표는 그대로 수집(오케스트레이션만 빠지고 검증 레일은 불변).
- **전환 절차**: 스모크 결과를 대표님께 1회 보고 → 대표님이 "A 확정 / 축소 / B / 보류" 택1. **런타임 자동 강등 금지**(사용자 인지 없는 모드 전환 방지). 롤백=세션 종료 + env 원복.

## D-3. 미결정 항목 (상위계획 §8) 기본값 제안

1. **PoC 대상 코드베이스**: mission-control 사용 (실 패턴·골든샘플 확보 용이). 단 §0 게이트대로 실 PII/보험/금융 코드는 제외·더미만.
2. **과제 A 디자인 시스템**: 기존 확정본(ui-methodology) 사용 — 신규 제작은 변수 증가.
3. **GPT-5.5 / Gemini 3.1 Pro 실접근**: 미보유 시 **GLM vs Claude 2모델 비교로 축소**(핵심은 GLM 편입 여부지 4모델 랭킹 아님).
4. **채점 인력 (대표님 확정 2026-07-02 = rubric 위임)**: 정량은 스크립트 자동, **정성(디자인)은 고정 rubric에 따라 위임 채점**(대표님 직접 채점 아님). rubric은 상위계획 §3 특화축(디자인 일관성/여백·정렬/반응형/재사용성 각 0~5)을 고정 기준으로 사용, 블라인드(모델명 제거) 유지. 대표님은 rubric 확정과 최종 Go/No-Go만 관여 → 채점 병목 제거(L2 `dd06668a` 해소).
