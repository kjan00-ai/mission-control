## 1. 구멍 — 한 글자로 게이트 전체가 열린다

하위명령(또는 명령 자체)을 따옴표로 감싸면 **모든 명령 규칙이 불발한다.** DENY 층도 예외가 아니다.

| 명령 | 라이브 등급 |
|---|---|
| `git clean -fd` | T2 |
| `git "clean" -fd` | **T1 (자율 실행)** |
| `git reset --hard` | DENY |
| `git "reset" --hard` | **T1** |
| `git checkout -- .` | DENY |
| `git "checkout" -- .` | **T1** |
| `git rebase -i HEAD~3` | DENY |
| `git "rebase" -i HEAD~3` | **T1** |
| `rm -rf /tmp/x` | DENY |
| `"rm" -rf /tmp/x` | **T1** |

홑따옴표 · 토큰 내부 따옴표(`cl""ean`) · 백슬래시(`\clean`) · 명령 자체(`"git" clean -fd`) 전부 같다.

**격리 repo 실동작 확증** — `git "clean" -fd` 는 게이트 T1 을 통과하고 작업물을 전부 삭제한다. 셸이 따옴표를 벗겨 git 에게 `clean` 으로 넘기기 때문이다.

### 노출은 잠복형이다

코퍼스 41,339 고유 명령에서 따옴표로 감싼 **명령/하위명령** 실사용은 사실상 0 이다(따옴표-머리 39건은 전부 `cd "경로"` 형태). `clean.requireForce` 와 같은 패턴이다 — **빈도 0 은 위험 0 이 아니라 아직 안 밟았다는 뜻**이고, 그때는 발견 몇 분 만에 밟혔다.

## 2. 원인 — 규칙 52개가 아니라 스캔 텍스트 한 곳

분류기는 두 갈래 스캔 텍스트를 만든다(`dangerScanText`=DENY·T3 / `headScanText`=T2). **둘 다 따옴표를 원문 그대로 둔다.** 원문 보존은 서브셸 우회를 잡으려는 의도적 설계였는데, 정작 **토큰을 쪼개는 따옴표**가 사각으로 남았다.

T2 쪽은 한 겹 더 있다. `headOfSegment` 는 헤드를 만들기 전에 인용문을 통째로 `_` 로 **치환**한다:

```js
const stripped = lead.replace(/\$\([^()]*\)/g, ' _ ').replace(/"(?:[^"\\]|\\.)*"|'[^']*'/g, ' _ ')
```

`git "clean" -fd` → `git _ -fd`. 내용이 사라지므로 **사후 보정으로는 복구되지 않는다** — 벗기려면 원문 단계에서 벗겨야 한다. (이 치환 자체는 없애면 안 된다. `node "/tmp/x.js"` 가 헤드 `node` 로 줄어 interactive 규칙에 걸리는 오탐 58건을 막는 장치다.)

## 3. 설계 — 벗긴 형태를 **추가로** 검사한다

```
[변경 전]  규칙 ← 원문 스캔텍스트
[변경 후]  규칙 ← 원문 스캔텍스트  OR  따옴표를 벗긴 스캔텍스트
```

원문 검사를 **그대로 두고 주체를 늘리기만** 한다. 그래서 이 패치로 등급이 **낮아지는 명령은 원리적으로 없다** — 완화 회귀가 설계상 불가능하다(주장이 아니라 OR 의 성질이다).

> ⚠️ **v0.4 에서 이 불변식은 절반만 남는다**(L2 `bca50bb8`). DENY·T3 레인은 여전히 OR 이라 완화가 불가능하지만, **T2 헤드 레인은 제거 범위를 좁히므로 등급이 내려갈 수 있다** — 코퍼스 157건이 T2→T1 로 내려간다(전부 v0.1 이 만든 오탐). v0.4 의 안전 근거는 "OR 의 성질"이 아니라 **규칙별 완화 분류 + 회귀 가드**다 → §9.

### 벗기는 범위를 좁힌다 — 공백 없는 토큰을 감싼 따옴표만

```js
function dequoteCmd(s) {
  if (!s || !/['"\\]/.test(s)) return null
  const out = String(s)
    .replace(/\\(?=[A-Za-z])/g, '')
    .replace(/"([^"\s\\]*)"|'([^'\s]*)'/g, (m, a, b) => (a !== undefined ? a : b))
  return out === s ? null : out
}
```

| 입력 | 결과 | 이유 |
|---|---|---|
| `git "clean" -fd` | `git clean -fd` | 토큰을 쪼개는 따옴표 → 벗긴다 |
| `cl""ean` | `clean` | 토큰 내부 따옴표 |
| `echo "hello world"` | 그대로 | **공백 포함 = 진짜 인자** |
| `ls -la "/tmp/some dir"` | 그대로 | 공백 경로 |
| `node -e "console.log(1)"` | payload 유지 | 래퍼 payload 규율 불변 |

벗긴 원문을 **같은 스캔 경로**(`dangerScanText`·`headScanText`)에 한 번 더 태운다. 마스킹·blankArgs·데이터싱크 규율이 그대로 적용되므로 기존 오탐 방어가 유지된다.

`$`·백틱(치환)은 건드리지 않는다 — 치환은 이미 다른 보수 규칙의 소관이고, 정적으로 펼칠 수 없다(§5).

## 5. 잔여 위험 — 이 패치가 닫지 **않는** 것

텍스트 게이트는 **간접화**를 원리적으로 못 닫는다. 실측(패치본 기준):

| 형태 | 패치 후 | 판단 |
|---|---|---|
| `S=clean; git $S -fd` | T1 ⛔ | 변수 간접 |
| `git $(printf clean) -fd` | T1 ⛔ | 명령치환 |
| `X=ean; git cl$X -fd` | T1 ⛔ | 부분 변수 |
| `git config alias.z "clean -fdx" && git z` | T1 ⛔ | alias 은닉(기지, 별건) |
| `echo <base64> \| base64 -d \| bash` | T1 ⛔ | 인코딩 |
| `eval "git clean -fd"` | T2 ✅ | eval 은 원문 유지 규율로 잡힌다 |
| `bash -c 'git clean -fd'` | T2 ✅ | 셸 래퍼는 원문 유지 |
| `git $'\x72eset' --hard` | **v0.2 T1 ⛔ → v0.3 DENY ✅** | ANSI-C **이스케이프**. 간접화가 아니라 *적힌 그대로 실행되는* 형태라 이 표의 예외다 → §9 |

**그래서 이 패치의 위협모델을 정직하게 적는다**: 막는 대상은 *적힌 그대로 실행되는 형태*다 — 에이전트가 무심코 쓰거나 편의로 따옴표를 두르는 경우. 작정한 우회를 막는 장치가 아니며, 그건 텍스트 게이트가 아니라 다른 층(실행 계측·사후 롤백)의 몫이다.

다만 닫는 값어치는 분명하다: 따옴표 형태는 **사전 준비가 필요 없고**(변수 설정도, alias 정의도, 인코딩도 없이) 그 자리에서 바로 실행되며, 실제로 DENY 층까지 관통한다.

## 8. v0.2 — L2 합의 4건 반영 (2026-09-13 라이브)

v0.1 을 적용한 뒤 돌린 L2(`evidenceEligible: true`)가 round 2 에서 **4건을 합의(corroborated)** 로 올렸고, **전부 라이브에서 재현됐다.** 즉 v0.1 은 "적용 완료"였지만 구멍이 열린 채였다.

| L2 id | 등급 | 내용 | v0.1 라이브 실측 |
|---|---|---|---|
| `f4708c26` | blocker | `$'…'`·`$"…"`(ANSI-C/로케일 인용)도 셸이 똑같이 벗긴다 | `git $'reset' --hard` → **T1(allow)**. DENY 층 관통 |
| `5c4bfa05` | blocker | `branchAllow`/`trustedAllow` 의 `denyIfRe` veto 가 원문만 본다 | `git commit --"amend"` [feat/*] → **T1(allow)**. 히스토리 재작성이 자율 실행 |
| `2661b190` | important | 따옴표 제거가 인용 안에서 죽어 있던 메타문자(`;`·`&&`)를 되살려 없던 세그먼트 분할을 만든다 | `echo "a;rm"` → T2 오탐 |
| `fa4ab4a3` | important | 공백 없는 payload 는 dq 레인에서 마스킹 근거(따옴표)가 사라진다 | 〃 (같은 뿌리) |

`577c3bb3`(Windows 동기가 수용기준 밖) 도 합의였다 → v0.2 는 `apply2.js` 가 **적용 직후 `maia-deploy` 를 직접 호출**하고 실패 시 비정상 종료한다. 미합의 1건 `19b9bdb3`(T3 배포를 T1 스크립트가 한다)은 대표 에스컬레이션으로 남아 있다 — §6 의 기지 항목과 같은 사안.

### 수정 셋

1. **`$` 접두 인용도 벗긴다** — 셸 동작과 일치시킨다.
2. **인용 내용에 셸 메타문자가 있으면 벗기지 않는다.** 그 따옴표는 토큰을 쪼개는 게 아니라 메타문자를 *무력화*하는 장치다. 벗기면 셸이 하지 않는 분할을 만든다(`2661b190` 의 원인). 같은 수정이 payload 노출(`fa4ab4a3`)도 줄인다.
3. **veto 를 dq 주체에도 적용한다.** veto 는 안전장치라 **원문·제거본 둘 중 하나만 걸려도 거부**한다. 반대로 `requireRe`(허용 조건)는 원문만 본다 — 완화 방향으로는 넓히지 않는다.

```js
.replace(/\$?"([^"\s\\;&|<>()`$]*)"|\$?'([^'\s;&|<>()`$]*)'/g, ...)
```

### ★ 설계 — 레인을 가른다

v0.3 은 "dq 레인이 **명령 위치의 토큰만** 벗긴다"였다. 오탐은 잡혔지만 L2 가 **되열린 구멍 3건**을 짚었다 — 전부 **인자 자리에서 매칭되는 규칙**이다.

| L2 id | 형태 | 라이브(v0.2) | v0.3 | 문제 |
|---|---|---|---|---|
| `bffb2295` | `gh pr crea"te" --title x` | DENY | **T1** | external-send 는 인자에서 매칭된다 |
| `52f591ea` | `git push origin "+main"` | DENY | T3 | force refspec 은 인자다 |
| `a0837ec0` | `git commit -m x $'\x2d\x2damend'` | **T1 allow(explicitAllow)** | T2 | 원문에 `-` 가 없어 플래그로도 안 보인다 |

셋째 줄은 v0.3 의 문제가 아니라 **지금 라이브의 구멍**이다 — feat/* 에서 히스토리 재작성이 게이트 없이 실행된다.

그래서 **비대칭**으로 간다. 엔진이 이미 쓰는 비대칭과 같은 결이다(`dangerScanText` 는 인용을 원문 유지, `headScanText` 는 `_` 로 가린다):

| 레인 | 제거 방식 | 이유 |
|---|---|---|
| **DENY · T3** (`dangerScanText`) | **전역** — 모든 토큰 | 차단력이 최우선. 인자 자리 규칙(external-send·force refspec·secret)을 지킨다 |
| **T2 헤드** (`headScanText`) | **위치 한정** | 오탐이 전부 여기서 났다(`migration` 126 등). 헤드 규칙은 실행 토큰만 보면 된다 |

위치 한정 규율은 다음과 같다.

| 토큰 위치 | 벗기는가 | 근거 |
|---|---|---|
| 세그먼트 선두(명령) | ✅ | `"rm" -rf` · `"git" checkout -- .` |
| 그 다음(하위명령) | ✅ | `git "clean" -fd` |
| 플래그 모양(`-`/`--`) | ✅ | `--"amend"` · `--no-ver"ify"` |
| `=` 를 품은 토큰 | ✅ (위치 미소모) | `VAR=x cmd` 접두 · `git -c user.name='maia' commit` — 소모시키면 진짜 하위명령이 인자 위치로 밀려 **미탐**이 된다 |
| 그 밖의 인자 | ❌ | `find … -name "migrations"` — 여기선 따옴표가 `headOfSegment` 의 오탐 방패다. 벗기면 방패가 사라진다 |

세그먼트 구분자(`;`·`&&`·`\|`·개행)를 만나면 위치가 0 으로 돌아간다.

추가로 **토크나이저가 인용을 인식한다.** 단순 공백 분할이면 `node -e "…여러 단어…"` 의 payload 앞부분이 하위명령 위치로 올라와 마스킹 근거를 잃는다(측정 중 probe 스크립트 2건이 DENY 로 튀어 발견). 대입 토큰 판정도 **선두 앵커**(`^[A-Za-z_][\w.-]*=`)로 한다 — 느슨하게 `=` 포함으로 잡으면 `node -e "const fs=require(…)"` 를 대입으로 오인한다. 반대로 대입은 공백을 품어도 벗긴다: `P="git pu""sh"` 처럼 **값 안에서 토큰을 쪼개는** 형태가 코퍼스에 실재한다.

**플래그 값과 러너 접두는 위치를 소모하지 않는다** — 엔진 `headTokens` 의 `expectValue`·`PREFIX_LEAD` 와 같은 규율을 그대로 복제했다(새 규칙을 발명하지 않는다). 소모시키면 진짜 하위명령이 인자 위치로 밀려 dq 레인에서 빠진다:

```
git -C /p "clean" -fd      →  bash: [git][-C][/p][clean][-fd]
sudo -u root "rm" -rf /x   →  bash: [sudo][-u][root][rm][-rf][/x]
timeout 5 "rm" -rf /x      →  bash: [timeout][5][rm][-rf][/x]
```

L2 `cf185bec` 가 이 창을 짚었고(3엔진 비교로 재현), **bash 로 실제 워드분할을 확인한 뒤** 규율을 넣었다.

**측정** (`patch4.js` 공용 조립 · `measure4.js` · `check4.js` · `apply4.js --check`, 코퍼스 41,811):

```
오탐  pre 대비 상승 : 193 → 40      (−153)
완화  pre 대비 하락 :   0            ← 기준선 이하로는 내려가지 않는다
완화  live 대비 하락: 157            ← 푸는 것. 전량 규칙별 분류 ↓
강화  live 대비 상승:   3            ← 조이는 것. 전량 확인 ↓
스모크 33/33 · risk-classify 237 · gate-destructive 124 · policy-classify 53
```

푸는 157건은 **전부 T2 규칙**이다 — `migration` 107 · `remote-run` 27 · `git-clean` 7 · `move-rename` 5 · `infra`/`pkg-install` 각 3 · `eval-exec` 2 · `git-commit:branch-gate`/`bulk-edit`/`interactive` 각 1. **T3·DENY 층은 한 건도 없다**(레인을 갈랐으니 원리적으로 그렇고, 실측도 그렇다). 형태는 히어독 본문·인용 경로 안의 단어다.

조이는 3건은 전부 **"위험한 명령을 언급하는 텍스트"** 다 — 이 세션의 probe 스크립트 2건과, `$'reset'` 를 본문에 담은 **내 커밋 메시지 1건**. 2026-09-07 대표 판정 (가)로 **수용된 오탐 계열**과 같다(heredoc 오탐 3건). 단, 이 트랙을 다루는 커밋 메시지가 DENY 를 맞을 수 있다는 뜻이므로 여기 적어 둔다.

> 측정·검증·적용이 **같은 조립 소스**(`patch4.js`)를 쓴다. v0.3 까지는 스크립트마다 앵커를 다시 적어 조용히 분기할 수 있었다.

> 중간 설계에서 한 번 **`git-push` 3건(T3→T1)·`force-push` 1건(DENY→T1)이 풀린 적이 있다.** 대입 토큰을 "공백 있으면 손대지 않는다"로 묶었더니 `P="git pu""sh"` 가 빠져나갔다. 분류를 규칙 단위로 찍어봤기에 잡혔다 — 총계만 봤으면 "완화 108건, 대부분 오탐" 으로 넘어갔을 것이다. **완화 패치는 총계가 아니라 규칙별로 본다.**

⚠️ **완화 방향 패치**라 [[gate-relaxation-needs-retention-check]] 규율을 적용했다: 기준선을 백업 파일로 고정하고, 합성 MUST_GATE 를 만들지 않고 **이미 라이브를 지키는 시험군 403건을 그대로** 태웠다.

**영구 가드 107 → 124건**: ANSI-C 이스케이프 5(16진·8진·유니코드·`rm -rf`·플래그) + **위치 회귀 7**(옵션 접두·플래그값·래퍼 옵션·러너 접두·env 대입·xargs·러너+하위명령) + **인자 위치 3**(`gh pr crea"te"` · `push origin "+main"` · 인자 위치 이스케이프 플래그) + 오탐 감시 2.

인자 위치 3건이 **두 레인 분리의 회귀 가드**다 — 누군가 "하나로 합치자"고 하면 여기서 깨진다.

위치 회귀 가드는 L2 `baea3a79` 의 지적에서 왔다 — *"완화 축 수용기준이 코퍼스와 기존 시험군으로만 측정돼 구조적으로 이 회귀를 못 잡는다. '빈도 0 은 위험 0 이 아니다' 원칙이 완화 방향에는 적용되지 않았다."* 맞는 지적이다. 코퍼스에 없는 형태라도 셸이 실행하면 위험이다.

⚠️ 다만 **합성 가드는 헛돌 수 있다**. 그래서 규율을 **제거한 변형 엔진**을 만들어 가드가 실제로 깨지는지 확인했다.
