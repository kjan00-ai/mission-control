## 1. 문제 — BC/SF 모달의 53%가 `remote-run`(npx)

BC/SF ask **8,733건** 중 규칙별 1위가 `remote-run` **4,641건(53%)**. 규칙은 `\bnpx\b|\bbunx\b|\b(pnpm|yarn)\s+dlx\b|\bpipx\s+run\b` — **npx를 무조건 T2**로 잡는다.

그런데 실체를 해부하면 "원격에서 임의 패키지를 받아 실행"이 아니다:

| 실행 대상 | 건수 | 성격 |
|---|---:|---|
| `vitest` | 1,748 | 로컬 테스트 러너 |
| `wrangler` | 1,146 | **Cloudflare 원격 리소스 도구 — 별도 취급(§3)** |
| `tsc` | 558 | 로컬 타입체크 |
| `eslint` | 411 | 로컬 린트 |
| `playwright` | 44 | 로컬 E2E |
| `next`·`esbuild`·`tsx`·`lint-staged` 등 | 45 | 로컬 빌드도구 |
| *인용문·grep 패턴 속 '언급'만* | *663* | *순수 오탐* |

**원격 강제 플래그(`-y`/`--yes`/`-p`/`--package`)는 3건, 버전 지정(`@x`)은 6건 — 합쳐 9건뿐**이다.

**핵심**: `npx vitest`는 `node_modules/.bin/vitest`를 실행하며, 이는 이미 T1로 자율 통과하는 `pnpm test`와 **동일한 동작·동일한 위험**이다. 같은 일을 하는 두 명령이 다른 등급을 받는 것은 규칙의 결함이다.

## 2. 설계 — 3중 조건 화이트리스트 (fail-safe)

`remote-run` 규칙이 매칭된 세그먼트에 대해, **아래 셋을 모두** 충족할 때만 T1로 내린다. 하나라도 불충족이면 **T2 유지**.

**조건 A — 원격 강제 플래그 없음**
`-y` · `--yes` · `-p` · `--package` · 패키지에 `@버전`(`@1.2.3`/`@latest`/`@next`) 이 있으면 **즉시 제외**. 이들은 레지스트리에서 받아오겠다는 명시적 의사표시다.

**조건 B — 로컬 개발도구 화이트리스트에 존재**
`vitest` `jest` `tsc` `tsx` `eslint` `prettier` `playwright` `next` `vite` `esbuild` `tsup` `rollup` `webpack` `lint-staged` `stylelint` `biome`
→ **화이트리스트(allowlist)이므로 미지의 패키지는 자동으로 T2 유지**. 블랙리스트와 달리 열거 누락이 안전 구멍이 되지 않는다.

**조건 C — 실제로 로컬에 설치되어 있음**
`evt.cwd`에서 상위로 올라가며(최대 5단계) `node_modules/.bin/<pkg>`(`.cmd`/`.CMD`/`.ps1`/`.exe`/`.bat` 포함) **파일 존재를 실측**하고 `realpathSync`로 심링크를 해소한다(끊긴 심링크 = 미설치). 없으면 원격에서 받아야 한다는 뜻이므로 T2 유지.
- `cwd`가 없으면(감사로그 기준 577/4,641 = 12.4%) 판정 불가 → **T2 유지**(보수적).
- 성능: 최대 5회 `existsSync`. 훅은 매 호출 새 프로세스이므로 캐시 없이도 무시할 수준.

### 2.1 파싱 규격 (L2 blocker `23fb637c` — 명문화)

판정은 **기존 `splitTopLevel()`로 분해한 세그먼트 단위**로 하며, 세그먼트마다:
1. 선행 env 대입(`FOO=bar `)을 제거하고 **첫 토큰이 `npx`인지** 본다. 아니면 그 세그먼트는 대상이 아니다 → **인용문·grep 패턴 속 `npx` 언급은 실행 위치가 아니므로 자연 배제**된다.
2. 이후 토큰을 좌→우로 스캔한다:
   - `--` 를 만나면 이후 **첫 토큰을 패키지**로 본다(그 뒤 옵션은 패키지 인자).
   - `--` 이전에 `-y` `--yes` `-p` `--package` `-c` `--call` `--registry` `--userconfig` 중 하나를 만나면 **즉시 실패**(원격 의사).
   - `--` 이전의 그 밖의 `-`로 시작하는 토큰은 건너뛴다.
   - 첫 비플래그 토큰 = **패키지 스펙**.
3. 패키지 스펙에서 이름을 추출한다: `@scope/name` 은 유지, `name@1.2.3`·`@scope/name@1.0.0` 처럼 **버전이 붙으면 실패**(원격 의사).
4. **한 명령 안의 모든 `npx` 세그먼트가 전부 통과해야** 완화한다. 하나라도 실패하면 명령 전체가 T2 유지. `npx` 실행 세그먼트가 하나도 없으면 완화하지 않는다.
5. 러너는 **`npx`만** 대상이다. `bunx`·`pnpm dlx`·`yarn dlx`는 '원격에서 받아 실행'이 의미상 기본이므로 제외한다.
6. 판정 중 어떤 예외가 나도 **T2 유지**(fail-safe).

**위협 모델 밖(L2 `f66a306f`)**: `existsSync` 판정과 실제 실행 사이의 파일 교체(TOCTOU)는 **로컬 쓰기 권한을 전제**하므로 본 게이트가 방어할 수 있는 대상이 아니다(그 권한이 있으면 이미 상위 위험이다). 판정은 게이트 등급 결정용이지 실행 무결성 보증이 아님을 명시한다.

## 3. `wrangler` 제외 — 실측에 근거한 결정

`wrangler`는 로컬에 설치돼 있어도 **원격 Cloudflare 리소스를 직접 조작**한다. 실측:

| | 건수 |
|---|---:|
| `wrangler d1` | 1,117 (그중 `execute` **1,112**) |
| ↳ `--remote`(**프로덕션 D1 직접 실행**) | **1,024** |
| ↳ `--local` | 89 |
| `wrangler deploy` | 123 |
| `secret` · `r2` · `containers` · `pages` · `queues` · `kv` · `versions` | 264(변경 가능 계열 합) |

`d1 execute --remote`는 프로덕션 데이터베이스에 임의 SQL을 실행한다(SELECT뿐 아니라 `INSERT`/`UPDATE`/`DROP`도 가능하며, `--file`로 마이그레이션 전체 적용도 가능). **되돌리기 어려운 외부 상태 변경**이므로 대표 게이트가 정당하다.

⇒ **wrangler는 조건 B 화이트리스트에 넣지 않는다.** 향후 `d1 execute --local`·`whoami`·`--version`·`deployments`(조회 계열)만 별도 분리하는 것은 후속 과제로 둔다.
