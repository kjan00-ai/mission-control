# git-commit branchAllow 브랜치 패턴 확대 spec (B2)

- **발단**: 대표 지시 *"B2 브랜치 패턴 확대만 진행"* — `d1` 패치 후 잔여 모달 1위가 `git-commit`(최근 14일 418건, 55.9%)으로 바뀌었다
- **선행**: [[2026-09-01-d1-read-sql-spec]](적용 완료). 커밋 호출 규약은 [[commit-standalone-call-for-branch-autonomy]]
- **변경 범위**: **정책 한 줄**. 게이트 코드는 손대지 않는다

---

## 1. 실측 — git-commit 418건의 정체

| | 건수 | 성격 |
|---|---|---|
| `feat/*` 인데 `requireRe` 미충족 | 263 (62.9%) | **호출 규약 위반** — 게이트 대상 아님 |
| **`fix/`·`docs/` 브랜치** | 84 (20.1%) | 본 spec 대상 |
| `master`/`main`/`master-sync` | 65 (15.5%) | **정당** |
| `branch` 미기록 | 4 (1.0%) | 판정 불가 |
| `feat/*` `denyIfRe` 매치 | 2 (0.5%) | 정당(체인·치환) |

263건은 `cd "…" && git commit -m "$(cat <<'EOF' …` 같은 형태로, 규약 ①단독호출 ②`cd` 금지 ③heredoc 금지를 어긴 것이다. 규약은 2026-08-31 전역 CLAUDE.md에 성문화됐고 일자별로 8/30 21건 → 8/31 **4건** → 9/1 **10건**으로 줄고 있다(이틀치라 추세 단정은 이르다).

브랜치 prefix 분포(최근 14일, 모달/전체 이벤트):

```
feat 265/296 · master 61/69 · fix 48/56 · docs 36/42 · main 3/5 · master-sync 1/1
```

`branchAllow.re`가 `^feat/` 뿐이라 **`fix/`·`docs/`가 T2로 남는다**. 이들은 보호 브랜치가 아니라 `feat/`와 같은 성격의 작업 브랜치다.

---

## 2. 설계

```diff
-  "re": "^feat/",
+  "re": "^(?:feat|fix|docs)/",
```

- **실측에 존재하는 prefix만** 넣는다. 초안은 Conventional Commits 표준 타입 8종을 넣었으나 L2 `600e94da`가 **미실측 5종(`chore`·`refactor`·`test`·`perf`·`style`)은 변경 범위 초과**라고 지적해 3종으로 좁혔다. 필요해지면 그때 실측과 함께 추가한다. `release/`·`hotfix/`는 배포 성격, `build/`·`ci/`는 워크플로·훅 편집이 섞일 수 있어 제외한다
- **안전장치는 그대로다** — `requireRe`(단독 `git commit … -m`/`-F`)와 `denyIfRe`(`--amend`/`--no-verify`/`&`/`|`/`;`/`$(`/백틱/개행)가 확대된 브랜치에도 **동일하게** 적용된다
- **슬래시를 요구**하므로 `master-sync`·`mainline`처럼 슬래시 없는 이름은 걸리지 않는다

### 방어 수준에 대한 정확한 진술

초안은 "방어 수준이 낮아지는 지점이 없다"고 썼으나 이는 과장이다(L2 `2401610a`). 정확히는 **브랜치 축에서만** 그렇다.

커밋 게이트는 **명령 텍스트만** 보므로 스테이징 내용을 모른다. 따라서 `fix/auth` 브랜치에서 고위험 파일이 스테이징된 채 단독 커밋하면 그 커밋은 자율 통과한다. 다만 이는 **`feat/`에 이미 존재하던 성격이고 본 변경이 새로 여는 위험이 아니다**. 고위험 파일 **편집**은 경로 규칙(`highRiskPaths`)이 확대된 브랜치에서도 그대로 막으며, 이 거동을 회귀 C군으로 못박았다(`src/lib/auth.ts`·`src/lib/scheduler.ts`·`migrations/*.sql` on `fix/`·`docs/`).

## 3. 실익 정정 — 84건이 아니라 7건

착수 시 "`fix/`+`docs/` = 84건"으로 추정했으나 **전수 replay 실측은 7건**이었다(`fix` 4 · `docs` 3).

**84건 중 77건이 `requireRe`/`denyIfRe`에도 함께 걸린다.** 브랜치만 풀어도 호출 형태 때문에 여전히 T2다:

```
git add CLAUDE.md && git commit -q -F - <<'EOF'     ← 체인 + heredoc
cd "D:/…" && node -e "…" && git add …               ← 체인
```

브랜치 분류만 하고 `requireRe`/`denyIfRe` 통과 여부를 보지 않은 것이 원인이다([[prioritize-by-measurement-not-assumption]]에 적은 교훈을 같은 세션에서 다시 어겼다).

**그럼에도 적용하는 근거**: 과거 로그는 규약 위반이 섞여 안 풀리지만, **앞으로 `fix/`·`docs/`에서 규약대로 단독 커밋하면 자율 통과**한다. 규약이 8/31에 성문화된 직후라 효과는 지금부터 발생하며, `feat/`가 받는 혜택을 같은 성격의 브랜치로 넓히는 것이다. 변경이 한 줄이고 강화 0이라 비용·위험이 모두 낮다.

## 4. 검증

### 정책 스키마 (apply 내장)

`branchAllow`·`requireRe`·`denyIfRe` 존재를 확인하고, 정규식을 직접 돌려 **미허용 15종**(`master`·`main`·`master-sync`·`mainline`·`release/`·`hotfix/`·`develop`·`wip/`·미실측 5종·`build/`·`ci/`)이 차단되고 **허용 3종**이 매치되는지 본다. 어긋나면 롤백한다.

## 5. 적용 — 승인·환경·부분실패

배포는 WSL canonical을 Windows로 복제해 **두 환경의 라이브 게이트를 동시에 바꾸는 외부 상태 변경**이다. 절차를 명시한다(L2 `e5f7f315`·`5973731c`).

**승인 주체**: 정책 파일(`decision-policy.json`)은 A2 자기보호로 **owner-only T3**다. 에이전트는 candidate만 준비하고 `apply`·`maia-deploy`·`rollback` 은 **대표 `!` 로만** 실행된다 — 게이트가 기술적으로 강제한다.

```bash
node ~/p1c/candidates/branch-allow/apply.js --dry    # 1) 드라이런 — 원본 미변경
node ~/p1c/candidates/branch-allow/apply.js          # 2) WSL 적용 (실패 시 자동 롤백)
node ~/.ai-bootstrap/maia-deploy.js                  # 3) Windows 동기
```

**각 단계의 확인 지점**

| 단계 | 성공 판정 | 실패 시 |
|---|---|---|
| ① 드라이런 | 앵커 유일 · 스키마 · 골든 237 · 회귀 8종 전건 | 원본 미변경, 그대로 중단 |
| ② apply | 위와 동일 항목을 실제 파일에 대해 재실행 | **자동 롤백**(정책 원본 복원) 후 종료 |
| ③ deploy | `SYNCED … byte-identical` 출력 | 아래 |

**부분 실패 — ② 성공 후 ③ 실패·중단**: WSL은 새 정책, Windows는 옛 정책인 **분기 상태**가 된다. 두 환경이 서로 다른 판정을 하므로 방치하면 안 된다.

```bash
node ~/.ai-bootstrap/maia-deploy.js --check    # drifted > 0 이면 분기 확인
node ~/.ai-bootstrap/maia-deploy.js            # 전진 복구: 재배포
# 또는 후진 복구:
node ~/p1c/candidates/branch-allow/rollback.js && node ~/.ai-bootstrap/maia-deploy.js
```

배포는 파일 복사라 **멱등**하므로 재실행이 안전하다. 어느 쪽으로 복구하든 마지막에 `--check`가 **0 drifted**여야 완료다.

**적용 후 검증**(본 세션에서 매 패치 수행): 양쪽 `md5sum` byte-identical · `--check` 0 drifted · 골든 픽스처 · 양 환경 라이브 게이트 실측.

롤백: `node ~/p1c/candidates/branch-allow/rollback.js` (+ 재배포). 정책 파일만 백업/복원한다 — 게이트 코드는 손대지 않으므로 복원 범위도 한 파일이다.
