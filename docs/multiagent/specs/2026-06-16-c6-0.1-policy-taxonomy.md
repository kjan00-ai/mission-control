## 1. 가역성 Taxonomy — R0~R3 판정 규칙 + 관측신호 (산출물 A)

> 분류기가 쓸 **판정 규칙 + 관측 가능한 신호**. "무엇을 어떤 메커니즘으로 되돌리나 + 잔여손실 + 제3자 소비"를 구체 command/path 신호로 환원.

| R | 정의 | 관측신호(분류기 MVP — 정규식/메타) | 복원 | 잔여손실 |
|---|---|---|---|---|
| **R0 완전가역** | 100% 원복 | git-tracked 편집·`git commit`·로컬 생성. 외부발신/무스코프삭제/설치 신호 **없음** | git revert·백업·트랜잭션 | 없음 |
| **R1 시간제한** | 창 안 취소 | 예약/지연 플래그·soft-delete·큐 등록(취소 API) | 큐취소·보존기간 | 창종료 시 R3 |
| **R2 부분복구** | 잔여 동반 복구 | 역연산 command 존재: `migration`(down)·pkg uninstall·mv/rename·**process-kill(재시작)**·own-repo push(전진revert) | 역연산 | 정합성/캐시/참조(복구보장) |
| **R3 비가역** | 사회·물리 복구불가 | 제3자 소비/발신: 외부메일·트윗·과금·secret노출·무스코프 대량삭제 | (없음, 사후완화) | 평판·금전·노출·물리 |

★ *디지털 가역성 ≠ 사회적 가역성*: `git revert`는 되지만 이미 읽힌 메일·유출된 키는 안 됨 → R3.

**판정 우선순위(보수, 과분류 보정)**:
1. 제3자 소비/발신/유출/과금 신호 → **R3**.
2. 역연산 command 존재(down·uninstall·재시작·전진revert) → **R2**. *down 미보장·데이터손실 신호(`DROP`·`--data`)면 R3.*
3. 예약/지연·취소가능 → **R1**.
4. git-tracked·로컬·트랜잭션 + 제3자 미소비 → **R0**.
- ★ **'애매하면 R3' 범위 제한(과분류·알림피로 방어)**: 위 1~4 신호가 *전혀 안 잡히는 미지의 외부효과 op*에 한해서만 R3 보수상향. 신호 명확(예: down 있는 migration)이면 그 R 확정 — 알려진 op를 R3로 일괄 올리지 않음. 보수상향분은 C6-0 신뢰계측 거짓상향률 샘플.

## 2. 위험(risk) 차원 — E-룩업의 두 번째 입력 (산출물 C-1)

> (R, **위험**)→E 룩업의 "위험" = *피해 규모·확률*. `riskFlags` 유무로 **저/고위험** 2분.

★ **E-위험 입력 ≠ V-escalator ≠ 사전가드 트리거 (codex BLOCKER r2 — §6.2 모순의 근원 해소)**: 세 가지를 분리한다.
- **E-룩업 '고위험' 판정 = 다음만**: ① **highRiskPaths 매치**(auth·dispatch·scheduler·relay·migrations·secret-code·hook·i18n/config·lockfile·package.json·생성물·.env + 게이트SSOT·`.maia/risk-override.json` §5.3) ② **high-damage command-flag**: privilege(sudo)·eval·secret. ③ diffEscalation 임계(loc>300·file>10).
- **operational commandRule**(pkg-install·remote-run·bulk-edit·move-rename·process-kill)은 **E-위험을 '고'로 만들지 않는다**. 대신 `requiredControls=[사전가드(스냅샷/드라이런)]` + **V escalator +1**(리뷰깊이↑)만 유발. → R2 저위험 → **E1**(자율+가드)로 귀결(불요 E2 승인 폭증 제거, gemini 60fbfe86 완화).
  - *단 그 op가 highRiskPath에도 걸리면*(예: pkg-install이 lockfile 수정) **고위험 승격** — 경로가 우선.
- **V-escalator(삭제·rename·테스트변경·정규식캡처·blast radius)**는 V축 스펙 소관 — E-riskFlag 아님. **테스트 변경 = E0(R0저위험), V만 +1**(v0.2 비결정성 해소 유지).

**저위험 = 위 ①②③ 어느 것도 아님**: src 일반코드·docs·tests·messages·operational command(가드만).

★ 같은 riskFlag가 E·V를 *각자* 올리고 audit `escalatedBy:{E,V}`로 원인 태깅.

## 3. (R, 위험) → E 룩업 + 효력게이트 (산출물 C-2)

| 가역성 R \ 위험 | 저위험 | 고위험 | always-deny |
|---|---|---|---|
| **R0** | E0 | E1 | DENY |
| **R1** | E2 | E2 | DENY |
| **R2**(복구보장) | E1 | E2 | DENY |
| **R3** | E3 | E3 | DENY |

**E 등급 → 통제 + 창 성격 (★ veto vs approval 정명)**:
| E | 통제 | 창 성격 | timeout |
|---|---|---|---|
| E0 | 자율 + 사후검증 | — | 즉시 |
| E1 | 자율 + 사전가드(스냅샷·드라이런·사전 L2) | — | 즉시(가드 후) |
| E2 | 지연 + **veto창(opt-out)** | 막지 않으면 진행 | **자동 실행**(R1) |
| E3 | 지연 + **승인창(approval, opt-in)** | 명시 승인 없으면 미진행 | **자동 차단**(R3) |
| DENY | 즉시 차단(absorbing) | — | — |

★ **veto(E2)≠approval(E3)**: E2 무응답=진행, E3 무응답=차단. E3 '교착'은 정의(비가역은 승인 없이 미진행) — 단 승인피로는 **배치 다이제스트 입도**(V-spec §4)로 관리(개별 모달 아닌 묶음 검토).

★ **효력게이트 `effectiveDecision` (codex BLOCKER — 조기소비 차단 + 스키마 강제)**:
- 레코드는 **라벨(`executionLevel`)과 효력(`effectiveDecision`)을 분리**. `executionLevel=E3`(항구 라벨) ≠ 실행 허용.
- `effectiveDecision` = E3 실행기(C6-4) 미가동 동안 **`deny`**. C6-4 가동 + 대표 명시활성(§7-1) 시에만 `delay_approve`.
- ★ **스키마 강제(codex important r2)**: `effectiveDecision`은 **필수 필드**. 소비자는 반드시 이 필드를 읽어야 하며, **누락·미인식 값·executionLevel만 읽는 구버전 소비자 = `classifier_failure` → DENY**(규약 아닌 데이터·스키마 검증 강제). C6-0.2는 레코드 schema 검증에 `required:[effectiveDecision]` 포함.

## 4. deny-reason 분리 evidence 규칙 (산출물 B·D)

| denyReason | 정의 | evidence 규칙 | E | effectiveDecision |
|---|---|---|---|---|
| **`hard_deny`** | 가역화 불가 + 승인 무의미(절대차단) | ① 이력/작업트리 파괴(force/delete/tag push·reset --hard·rebase·clean -f) ② secret 노출/전송 ③ 무스코프/민감 대량 fs파괴(rm-rf §5.1·dd·mkfs) ④ RCE(curl\|sh·$(curl)·download-exec·procsubst·rc-write·forkbomb) ⑤ 게이트 자기변조(§5.3) ⑥ **외부발신 abuse**(아래 ★) | DENY | deny |
| **`r3_residual`** | 비가역 잔여 + 정당워크플로 + 승인 의미 | 진짜 외부발신(외부메일·트윗·과금·외부공개 댓글) — abuse-flag 無 | E3 | deny→delay_approve(§3) |

★ **외부발신 abuse-flag 운영 evidence (codex important r2 — `gh issue -b "$(cat id_rsa)"` 보장)**: 발신 command(mail/gh/slack/tweet/hermes send)가 다음을 본문/인자에 동반하면 **hard_deny**:
- secret-file read 치환: `$(cat …)`·`$(< …)`에 secret 경로(id_rsa·.env·credential·.pem·.ssh) 포함.
- secret 경로 리터럴 직접 인용 / env secret 변수: `$*KEY`·`$*TOKEN`·`$*SECRET`·`$*PASSWORD`.
→ 현 `secret-exfil` 정규식(curl/wget/http 한정)을 **발신 command 계열로 확장**. abuse evidence는 §1 알고리즘 1단계(hard_deny 우선)에서 평가 — r3_residual로 안 내려감.

**판정 알고리즘(순서)**: 1) hard_deny ①~⑥ → DENY. 2) R3 + 정당워크플로 → r3_residual/E3(eff=deny). 3) 그 외 → §3 룩업. *hard_deny가 r3_residual보다 우선(배타).*

## 5. R3 비가역 잔여목록 (산출물 B)

### 5.1 hard_deny (→ DENY)
force-push · delete-ref · tag-push · git-destructive · **rm-rf(무스코프/민감, 아래)** · fs-destructive · secret-file · secret-exfil · pipe-to-shell · shell-procsubst · shell-rc-write · forkbomb · curl-subst · download-exec · **외부발신 abuse**(§4-⑥).

★ **rm-rf 3분법 + path 정규화 (gemini BLOCKER + codex important r2)**:
1. **canonical 경로로 resolve 후 판정**(symlink 따라간 실경로 기준). trailing slash 정규화. **심링크가 허용dir→민감경로로 탈출하면 hard_deny**(허용보다 hard_deny 우선).
2. 분기:
   - **(a) git-tracked 경로**(소스 dir 포함, `rm -rf src/old_module`): git에서 복구가능 → **R0/R2 → 허용(E0/E1)**. hard_deny 아님.
   - **(b) git-untracked 빌드산출물·임시**(dist/.next/build/node_modules/coverage·프로젝트내 /tmp, 프로젝트 소유): 재생성물 R0 → **허용(E0/E1)**.
   - **(c) 무스코프(`/`·`~`·`$VAR`·상위경로·bare `*`)·민감경로(.git·secret·.ssh·홈·프로젝트 밖)**: **hard_deny**.
- `[기획결정]`: 허용 dir 화이트리스트·소유권 검사 정밀도는 C6-0.2 구현(현행 `generated` highRiskPath와 정합).

### 5.2 r3_residual (→ E3 라벨, effectiveDecision=deny until C6-4)
- **진짜 외부발신**: 외부 수신자 메일·sendmail·트윗·외부공개 댓글·과금/외부 mutation API — *팀의 회수통제 밖 수신자*.
- ★ **차등(gemini important r2 — 묻지마승인 방지)**: **own-repo·회수가능 발신은 r3_residual 아님**:
  - own-repo feature push(비-protected): 전진 revert 가능 → **R2 → E1**.
  - gh pr/issue **create**·own-repo comment: close/delete 가능 → **R2 → E1**.
  - → E3 승인 부하를 *진짜 비가역 외부발신*으로 한정. 고빈도 워크플로(push/PR)는 E1 자율+가드.
- `[기획결정]` 경계: protected/main push·merge·gh pr merge = §7. "회수가능"의 정확한 선(외부공개 PR vs 사설 repo)은 프로젝트별.

### 5.3 게이트 자기보호 (C6 §6.2 선반영)
- **게이트 SSOT 경로** = `**/.ai-bootstrap/{decision-policy.json,risk-classify.js,maia-manifest.json}` · `**/.claude/hooks/**` · settings.json hook 등록부 · **`**/.maia/risk-override.json`**(프로젝트 override 병합 공격면).

### 6.4 interactive = 운용성 게이트 (blocking + pty 예외)
가역성·위험 아닌 **교착방지** 게이트. 레코드 `{executionLevel:null, blocking:true, reason:'operability/deadlock'}`. ★ **pty 예외(gemini important r2)**: blocking=true는 **실제 tty-attached 대화형 호출만**. **pty/expect 래퍼·stdin redirect(`< file`)·파이프 입력 비대화형 자동화는 예외(blocking=false)** — 합법 자동화 스크립트 차단 방지. 휴리스틱: stdin이 tty가 아니거나 expect/script 래퍼 동반이면 비대화형으로 간주.

### 6.5 분류기 실패 폴백 (fail-open↔fail-safe + 스키마)
- **게이트 판정 경로 = fail-safe**: 분류기 reduce 실패 OR **`effectiveDecision` 등 필수필드 누락/미인식** → `{executionLevel:DENY, verificationDepth:V3, effectiveDecision:deny, denyReason:'classifier_failure'}` 강제.
- **denylist는 항상 fail-closed**(우회금지) — 그 위 R/E 추론 실패만 DENY 폴백.
- golden fixture에 `classifier_failure→DENY/V3` + `effectiveDecision누락→DENY` 행, CI가 폴백 누수 가드.
